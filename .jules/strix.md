## 2026-08-26 - Strix provider/backend failures
**Learning:** A Strix provider, gateway, rate-limit, or credit failure is an evidence gap, not proof that the change is safe and not a reason to edit unrelated product code. Security admission remains fail-closed: inspect the exact job log, record the run and head SHA, keep the pull request Draft/Proposed while authoritative evidence is missing, and repair a repository defect only when the log demonstrates one. Model-backed workflows must use the `orchestrator/free` gateway-only contract and must not select a provider, model, group, or paid fallback directly.
**Action:** Preserve the failed check as evidence. Retry only after the transient dependency has recovered or its canonical owner has been repaired; never ignore, bypass, or repeatedly resubmit a failed security check to manufacture admission.
